# 第三阶段报告：历史棋盘复原、界面升级与可玩性验收

## 1. 历史棋盘复原（重要：受限说明）

### 1.1 参考图片获取情况

| 图 | 来源 | 状态 |
|---|---|---|
| 1 | tshop.r10s.com 雷鸟牌 LT-215 | ✅ 已下载（600×600 JPEG） |
| 2 | pimg.1px.tw 历史三军棋实物 | ✅ 已下载（800×600，Canon 实拍） |
| 3 | collections.culture.tw 台湾历史博物馆影像 | ❌ 下载超时 |

**关键限制**：当前对话所用模型不接受图像输入，无法直接「读图」；OpenCV 图像分析只能提取到「**海洋居中、陆地在两侧**」的粗略格局（与现重建布局一致），**无法从照片可靠提取逐点坐标**。

### 1.2 结论与诚实声明

- **不得虚构已经核实的节点**：当前 `data/board.json` 仍为「文字重建布局」（`status: RECONSTRUCTED`），每个节点的 `source` 字段均为 `textual_reconstruction`。
- 已**确认（文字来源）**的节点类型：兵站、城市、行营、锚点、机场、铁桥、桥头、航线黑点。
- **坐标/数量**（如每方兵站数量、锚点位置、航線走向）均为**推断**，未逐一核实。
- **被遮挡节点**：因无法读图，无法标记。

### 1.3 需人工提供的截图清单

见 `data/board.json` → `meta.verification.needed_from_human`，核心 5 项：

1. 雷鸟牌棋盘**正上方平视、无阴影、无棋子**的高清图（或逐格标注版）。
2. 中央海域的**锚点/航行线位置**图。
3. **铁桥与桥头**的准确拓扑（桥跨几格、桥头在哪几格）。
4. **机场与航线黑点**的准确位置与航線走向。
5. 每方**兵站/城市/行营**的准确数量与坐标。

> 引擎数据驱动：一旦取得上述影像，只需替换 `board.json`（并运行 `python3 data/emit_esm.py`），规则引擎与 UI 无需改动。

## 3. 界面升级

- 菜单 / 规则说明（按陆/海/空分类查看 30 种棋子与战斗关系、冲突/假设清单）。
- 双方**手动布阵** + 自动布阵 + 重新布阵 + 布阵合法性提示（托盘选子→点合法格）。
- 选中棋子与**合法移动/攻击高亮**；交战**结果提示**；当前行动方/回合/存活统计。
- **存档/恢复**（localStorage）、**认输**、**撤销**（仅移动，交戰/偵察后不可撤销以防泄密）、返回菜单、结束弹窗。
- **暗棋双人交接**：全屏交接遮罩（接手确认）；敌方未揭示棋子显示统一背面「?」；侦察结果仅对侦察方显示。
- 视觉：陆暖色/海蓝、铁/公/海/空四类线型与颜色、城市/行营/机场/锚点/桥/桥头/黑点图形标识、30 种棋子独立色标+等级角标、窗口缩放自适应。
