# 航空系统专项审计与修复报告（第四阶段）

## 1. 问题复现与定位

用户报告两个核心缺陷：
1. 海上航空线路「看似相连」但飞机无法沿线路移动。
2. 战斗机无法攻击侦察机。

### 1.1 逐环节审计结果

| 环节 | 检查方法 | 结论 |
|---|---|---|
| 169 节点 / 271 边加载 | `BOARD.nodes`、`graphEdges` 计数 | 正确（169/271/16/88） |
| 空军邻接关系 | `airRuns[].stops` → `edges.air_lines` | 18 条航線、66 个空中停靠点，全部在运行图中 |
| 机场↔主航线连接 | 四机场 `airLinesOf` | FNW/FNE/FSW/FSE 均在 2 条航線上 |
| 海上航線是否被误判为海军 | `allowedPieceClasses` | 空中节点均为 `air`，与 `sea` 分离 |
| 航段在黑点连接 | 航段相邻对 vs 运行图 | 104 段，视觉 air_lane 边与引擎站对**完全一致**（104=104） |
| 连续直线判定 | `airMoveTargets` 同 run 内移动 | 正确（不跨 run，转弯需停留） |
| 飞机转弯停留 | 多回合测试 | 正确（单次行动只在一条航線内） |
| 陆海军是否阻断飞机 | 放置地面/海面棋子后再测 | **不阻断**（空中与地面分层） |
| 飞越关系 vs 通行边 | `overflightByEdge` 仅用于攻击/侦测/防空 | 未混入通行判定 |
| UI 高亮 vs 引擎 | 浏览器实测 | 一致（13 个合法落点 / 13 个高亮 / 点击即执行） |

**连通性实测**：66 个空中停靠点构成 **1 个连通分量**（经航段邻接），单次直飞可达 **5–15** 个站点。四座机场均可起飞。

### 1.2 结论：真正缺陷是「空对空攻击」，而非移动

- **移动本身正常**：飞机可沿航線直飞、可在黑点停靠后转向、陆海军不阻挡。
- **找到并修复的真实缺陷**：`fighterAttackTargets` 仅使用 `air_line_cells`（航線下方地面/海面投影），**未包含同航線的空中黑点**。导致战斗机/侦察机**无法把敌方飞机识别为攻击/侦察目标**——这正是「战斗机无法攻击侦察机」的根因。
- 另外在视觉重构过程中引入并即时修复了「布阵按钮无监听器」的回归缺陷（浏览器实测发现）。

### 1.3 数据层面的「看似相连实则断开」（A 类，非缺陷）

历史棋盘数据中，第 1 列与第 6 列的竖向航線在行 2 与行 3 之间**确实断开**（`V1.1` 只到 A2-1、`V1.2` 从 A5-1 起；`V6.1` 只到 A2-6、`V6.2` 从 A5-6 起）。这是冻结图 v2.0.0 的真实拓扑，**不修改**。飞机需经横向航線绕行（如 A2-1→A2-3→V3→A3-3→A3-1），多回合可达。

## 2. 修复内容

### 2.1 空对空攻击（核心）

`src/core/moves.mjs` 的 `fighterAttackTargets` 现同时纳入：
1. **同一航線上的其他空中黑点**（可攻击/侦察敌方飞机）；
2. 航線下方地面/海面投影（飞越攻击/侦察）。

并对目标去重、过滤 `forbidden`。

### 2.2 其他

- 视觉重构中补回 `btn-auto` / `btn-reset-setup` / `btn-finish-setup` 监听器。
- 新增航空调试视图（选中飞机时显示所在航線、合法目的地、可攻击目标、不可达原因）。
- 棋盘/棋子视觉重构（见 §4）。

## 3. 战斗机 vs 侦察机 实测结果

| 场景 | 结果 |
|---|---|
| 矩阵单元 `fighter→scout_plane` | `attacker_wins` |
| 矩阵单元 `scout_plane→fighter` | `defender_wins` |
| 引擎：红战斗 A1-3 攻击 黑侦察 A1-2 | 合法，侦察机被消灭，战斗机存活于 A1-3 |
| 浏览器：红战斗 FNW 攻击 黑侦察 FSW（同属竖航線 VW） | 合法，侦察机被消灭，统计 红30:黑28 |
| AI 自动对局（20 局） | 战斗机↔侦察机遭遇 6 次，**6 次均由战斗机击杀侦察机** |

> 侦察机主动攻战斗机 = 侦察机被消灭（`defender_wins`），不会因是侦察单位而免疫。

## 4. 视觉重构

- **棋子**：半径由相邻节点最小间距推导（约 21px，较原 12.5 增大 68%）；军种图标（陆军三角/海军船体/空军机翼/军旗）；阵营配色（红/黑）；军官与舰艇等级角标；棋背为织纹+阵营宝石（非灰色问号）；选中/可移动/可攻击/受威胁四种状态反馈；阴影与描边。
- **棋盘**：海洋沉稳蓝色（渐变带）、陆地暖沙色；公路/铁路/铁桥/海路/航空线不同线型与配色；特殊节点（城/营/场/锚/桥/头）标识；**线路显示模式**：全部/陆军/海军/空军/智能（智能模式选中棋子后突出相关线路、其余淡化）。
- **视角**：自动适应窗口、滚轮缩放（以光标为中心）、拖拽平移、双击/按钮重置、选中棋子自动聚焦。
- 历史棋盘节点与线路几何关系**未改变**（仍由 `graphEdges` 渲染）。

| 反馈 | 处理 |

| 陆军与空军停留点应有差别 | 节点按类型绘制不同形状：**陆军兵站=圆**、**空军停靠点(air_dot)=菱形**、**机场=带机翼菱形**；另有城市方块、行营绿圆、锚点蓝圆(带锚形)、桥矩形、桥头三角。空中 66 个停靠点全部渲染为菱形，与陆军圆点一眼可分。 |

## 8. 航空水平连通性补丁（用户反馈「空军无法直接横向过去」）

### 8.1 定位

对 66 个空中停靠点做「视觉同排近邻（|Δy|<40、60<|Δx|<160）」与「是否同航線连通」的交叉检查，发现 **4 对视觉相邻却未连通**：

| 空点对 | 水平距离 dx | 垂直差 dy | 所在行 |
|---|---:|---:|---|
| A3-1 ↔ AW3 | 88 | 1 | 第 3 行 |
| A3-6 ↔ AE3 | 89 | 1 | 第 3 行 |
| A4-1 ↔ AW5 | 88 | 1 | 第 4 行 |
| A4-6 ↔ AE5 | 92 | 0 | 第 4 行 |

原因：冻结图 v2.0.0 的 `H3.1`（仅 A3-1..A3-6）与 `H4.1`（仅 A4-1..A4-6）**未包含西/东边缘空点**，而第 0/1/2/5/6/7 行均通过 H0/H1/H2/H5/H6/H7 与 AW/AE 连通。故第 3、4 行的西/东边缘空点只能沿西/东竖向航線（VW/VE）移动，无法横向进入本行。

### 8.2 修复（引擎层补丁，不改冻结数据文件）

- `src/core/board.mjs` 加载后应用 `AIR_PATCH`：把 `AW3/AE3` 并入 `H3.1`、`AW5/AE5` 并入 `H4.1`（补齐 4 条水平航段）。
- 同时导出 `AIR_PATCH_EDGES` 供界面绘制这 4 条边；**未写入 `graphEdges`**，`data/board.json` 保持冻结不变（169 节点 / 271 边）。
- 界面实测：航空线由 104 条变为 **108 条**（新增 4 条）；红战斗在 AW3 的合法移动含 **A3-1**。

### 8.3 说明

- 该补丁是**有据可查的补齐**（同排近邻证据 + 其余各行均连通），非重新设计拓扑；冻结 `data/board.json` 未修改，若后续 Codex 发布正式修订可移除本补丁。
- 补丁航段的「飞越投影」未新增（仅补齐通行），因此飞机可横向移动但不会沿该新段产生新的地面飞越目标；如需可另补。

## 9. 中间横线补丁 + 战斗机击杀后移动（用户补充反馈）

### 9.1 中间横线

海面中排（y≈600）只有西/东边缘空点 `AW4`/`AE4`，冻结图 v2.0.0 无横向航段，导致中间「一道」缺失。补丁：新增航線 `HMID = [AW4, AE4]`（飞越其下方海面 `M2-1..M2-7`），并导出渲染边（`AIR_PATCH_EDGES` 含 `via` 中继）。实测 `AW4` 可直飞 `AE4`；界面航空线由 108 → **109** 条。

### 9.2 战斗机击杀后移动到目标格

原 `attackIsDirect` 对战斗机一律返回 `false`（飞越不移动），导致战斗机击杀空中目标后停在原位。现改为：
- **空对空**（目标在空中黑点）：`direct=true`，击杀后**飞抵目标所在黑点**（如 A1-3 击杀 A1-2 的侦察机后停在 A1-2）；
- **空对地/海**（飞越攻击）：仍为 `direct=false`，战斗机留在原空中格（符合飞越轰炸语义）。

实测（浏览器）：红战斗机 A1-3 击杀黑侦察机 A1-2 后，`fighter.cellId=A1-2`、侦察机 `dead=true`；截图 `docs/screenshots/18-fighter-moves-to-target.png`。

### 9.3 回归

`npm test` → **57 项通过**；`npm run test:legacy` → 56 项通过；10 局航空模拟 10/10 结束、0 非法、115 次空战、战斗机 4/4 击杀侦察机。

## 10. 海面边缘补点（用户反馈「海军少了4个点，铁桥下方」）

### 10.1 定位

海面（M 行）节点分布：
- M0 / M2 / M4 行各 **7 点**（x≈39–815）；
- M1 / M3 行仅 **中间 4 点**（x≈234–618），**缺少西/东边缘各 2 点**（分别位于两条跨海铁路桥 x≈112 与 x≈739 下方）。

故共缺 **4 点**。

### 10.2 补丁（引擎层，不改 data/board.json）

在 `board.mjs` 顶部（邻接表构建之前）加入 `SEA_PATCH_NODES`：
- 新增 `M1-0`(x≈0.12,y≈0.448)、`M1-5`(x≈0.882,y≈0.448)、`M3-0`(x≈0.12,y≈0.562)、`M3-5`(x≈0.882,y≈0.562)，类型 `sea`、`side=neutral`、`allowedPieceClasses=['sea']`；
- 每条连接 4 个海路邻居（如 M1-0 ↔ M0-1/M0-2/M2-1/M2-2），使海面恢复完整梅花桩。

实测：海面节点 29 → **33**；四个新点各 4 条海路；`data/board.json` 未改动。

### 10.3 附带修复：取消点击自动居中

用户反馈「点击棋子就定位中心，影响操作」。已移除选中棋子时的 `focusOn` 自动平移；保留滚轮缩放、拖拽平移、双击/按钮重置视角。实测：选中棋子前后 `app.view` 不变。
